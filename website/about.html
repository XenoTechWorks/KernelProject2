About

A program never talks to the hardware itself. When it wants to read a file or print something, it asks the kernel with a system call: a number plus some arguments. On Linux, read is 0, write is 1 and execve is 59.

KernelProject2 answers those same numbers the same way Linux does. If it gets the answers right, a Linux program can't tell it isn't on Linux. This is the trick WSL1 used. It means I don't have to port anything: I take a program out of Ubuntu, copy it in, and see what breaks. When a program asks for a call the kernel doesn't have yet, the kernel logs it, and that's usually the next thing I write.

What's in it

About 150 system calls so far, out of Linux's 450 or so.

Languages

The kernel is Rust (nightly). The shell, the command line tools and the graphical toolkit are Zig, built without a C library: they make system calls directly. The Windows layer is C++, since the Windows calling conventions are easier to match there. Build scripts are shell and the tests are Python.

Tests

Each test boots the kernel in QEMU, types into it like a person would, and checks what comes back. Some click the mouse or take screenshots. The C test programs are also run on real Linux, and the two outputs have to match.

What it doesn't do (yet)

  • The kernel runs on one CPU at a time (programs run on all of them), and a program's threads take turns on one CPU.
  • An installed disk boots with UEFI only, not old BIOS firmware.
  • It has only been run in QEMU, not on real hardware.
  • No graphics card drivers. It draws to the framebuffer the bootloader gives it.
